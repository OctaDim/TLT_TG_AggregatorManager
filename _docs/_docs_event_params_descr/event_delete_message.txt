ПОЛНЫЙ СПИСОК ПАРАМЕТРОВ ДЛЯ events.MessageDeleted.Event В TELEGRAM/TELETHON

================================================================================
ОСНОВНЫЕ ПАРАМЕТРЫ СОБЫТИЯ MessageDeleted.Event
================================================================================

MessageDeleted.Event генерируется, когда сообщение(я) удаляются.

1. original_update - UpdateDeleteMessages/UpdateDeleteChannelMessages - Исходный объект обновления от Telegram API
2. pattern_match - Match или None - Результаты сопоставления с регулярным выражением из фильтра (обычно None)
3. _client - TelegramClient - Ссылка на клиент Telethon (внутреннее использование)
4. _chat - Chat/Channel/User или None - Кешированный объект чата/диалога
5. _entities - Dict[int, Union[User, Chat, Channel]] или None - Словарь кешированных сущностей
6. _message_ids - List[int] - Список ID удаленных сообщений
7. _deleted_messages - List[Message] или None - Кешированные объекты удаленных сообщений
8. _peer - Peer или None - Peer чата/диалога
9. _channel_id - int или None - ID канала (если применимо)
10. _broadcast - bool - Флаг, является ли чат каналом/супергруппой
11. _pts - int - PTS из обновления
12. _pts_count - int - PTS_COUNT из обновления
13. _is_channel - bool - Флаг, является ли событие из канала

================================================================================
ТИПЫ original_update ДЛЯ MessageDeleted.Event
================================================================================

1. UpdateDeleteMessages - Удаление сообщений в личном чате/группе
2. UpdateDeleteChannelMessages - Удаление сообщений в канале/супергруппе

================================================================================
ПАРАМЕТРЫ UpdateDeleteMessages
================================================================================

Используется, когда сообщения в личном чате или группе удаляются.

• messages - List[int] - Список ID удаленных сообщений
• pts - int - PTS (sequence для обновлений)
• pts_count - int - Количество PTS

================================================================================
ПАРАМЕТРЫ UpdateDeleteChannelMessages
================================================================================

Используется, когда сообщения в канале/супергруппе удаляются.

• channel_id - int - ID канала
• messages - List[int] - Список ID удаленных сообщений
• pts - int - PTS (sequence для обновлений)
• pts_count - int - Количество PTS

================================================================================

================================================================================

1. deleted_ids - List[int] - Список ID удаленных сообщений

9. chat - Chat/Channel/User или None - Объект чата (если доступен в кеше)
10. broadcast - bool - Является ли каналом с широковещательными сообщениями

12. pts_count - int - PTS_COUNT из обновления

МЕТОДЫ СОБЫТИЯ MessageDeleted.Event
================================================================================

ОСОБЫЕ СЛУЧАИ ДЛЯ MessageDeleted.Event:
================================================================================

1. Массовое удаление:
   - Администратор очищает историю
   - Удаление всех сообщений пользователя
   - Очистка чата при выходе
   - Может содержать сотни сообщений

2. Самоуничтожение сообщений:
   - Сообщения с ttl_period
   - Фотографии/видео с ограничением времени просмотра
   - Secret Chats (зашифрованные чаты)

3. Удаление в каналах:
   - Только администраторы могут удалять
   - Могут удаляться сообщения от других
   - Удаление постов с комментариями

4. Удаление в супергруппах:
   - Администраторы и иногда участники
   - Удаление только своих сообщений (для обычных пользователей)
   - Удаление с уведомлением всех

5. Системное удаление:
   - Удаление системой Telegram (спам, нарушение правил)
   - Автоматическое удаление старых сообщений
   - Очистка кеша сервера

================================================================================
ОГРАНИЧЕНИЯ И ОСОБЕННОСТИ:
================================================================================

1. Доступность данных:
   - Сообщения могут не быть в кеше клиента
   - get_messages() возвращает только кешированные сообщения
   - Невозможно получить удаленные сообщения с сервера

2. Тайминги событий:
   - Событие может приходить с задержкой
   - Могут быть пропущены некоторые удаления
   - В больших каналах события могут группироваться

3. Ограничения массового удаления:
   - Telegram ограничивает количество одновременно удаляемых сообщений
   - Flood control при частых удалениях
   - Ограничения для новых пользователей/чатов

4. Права доступа:
   - В личных чатах: оба участника могут удалять свои сообщения
   - В группах: зависит от настроек и прав
   - В каналах: только администраторы

================================================================================
МЕТОД get_messages() - ПОВЕДЕНИЕ:
================================================================================

1. Возвращает только сообщения, которые были в кеше клиента
2. Если сообщений нет в кеше - возвращает пустой список
3. Для получения сообщений из истории нужно предварительно их загрузить
4. Не делает запросов к API Telegram для получения удаленных сообщений
5. Кеш очищается при перезапуске клиента

================================================================================
ОБРАБОТКА ОШИБОК:
================================================================================

1. ChatNotFound - Чат не найден (удален или недоступен)
2. ChannelInvalidError - Канал недействителен
3. ChannelPrivateError - Канал приватный
4. AuthKeyError - Проблемы с аутентификацией
5. FloodWaitError - Слишком много запросов

@client.on(events.MessageDeleted())
async def archive_system(event):
    messages = await event.get_messages()
    if messages:
        for msg in messages:
            archive_entry = {
                'chat_id': event.chat_id or event.channel_id,
                'message_id': msg.id,
                'sender_id': msg.from_id.user_id if isinstance(msg.from_id, PeerUser) else None,
                'text': msg.text,
                'media': bool(msg.media),
                'date': msg.date,
                'deleted_at': datetime.now(),
                'chat_type': 'channel' if event.is_channel else 'group' if event.is_group else 'private'
            }
            await save_to_archive(archive_entry)

@client.on(events.MessageDeleted(is_group=True))
async def moderation_report(event):
    if event.count > 5:  # Массовое удаление
        chat = await event.get_chat()
        messages = await event.get_messages()

        report = f"""
        ⚠️ МАССОВОЕ УДАЛЕНИЕ
        Группа: {chat.title}
        Удалено сообщений: {event.count}

        Примеры удаленных сообщений:
        """

        for i, msg in enumerate(messages[:5], 1):
            sender = await msg.get_sender()
            sender_name = sender.first_name if sender else "Неизвестно"
            report += f"\n{i}. От {sender_name}: {msg.text[:100]}..."

        await send_to_moderators(report)

async def channel_analytics(event):
    stats = {
        'channel_id': event.channel_id,
        'deletion_time': datetime.now(),
        'message_count': event.count,
        'min_id': event.min_id,
        'max_id': event.max_id,
        'is_bulk': event.is_bulk,
        'pts': event.pts,
        'pts_count': event.pts_count

    # Обновить статистику канала

    channel_stats.total_deletions += event.count
    channel_stats.last_deletion = datetime.now()

ВАЖНЫЕ ЗАМЕЧАНИЯ:

1. Событие приходит только для сообщений, которые были получены клиентом
2. Невозможно получить содержимое удаленных сообщений с сервера Telegram

5. Для полного отслеживания удалений нужен постоянный кеш сообщений
6. Событие может быть пропущено при потере соединения
7. PTS помогает отслеживать порядок событий, но не гарантирует полноту
